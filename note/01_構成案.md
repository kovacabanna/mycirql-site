# note 記事の構成案（MyCIRQL 認知拡大用）

## 0. この記事のゴールを1つに絞る

note で「アプリを知ってもらう」記事を書くとき、いちばん失敗しやすいのが
**「全機能を紹介しようとして、誰の記事かわからなくなる」** パターンです。

なので、この記事のゴールは1つだけに絞ります。

> **読者に「あ、これ自分のことだ」と思わせて、App Store のリンクを踏んでもらう。**

機能を理解してもらうのはアプリを開いてからで十分です。
記事の役割は「自分ごと化」までです。

---

## 1. 全体の骨組み（推奨）

note の読者は「上から順に読む」より「スクロールしながら図を見る」ので、
**見出し → 短い文 → 図** の3点セットを1ユニットにして、それを9回くり返す形にします。

| # | セクション | 役割 | 図 | 目安の文字数 |
|---|---|---|---|---|
| 1 | つかみ（問いかけ） | 読者を立ち止まらせる | 図1 | 150字 |
| 2 | 作ろうと思ったきっかけ | 共感と信頼をつくる | － | 500字 |
| 3 | で、どんなアプリ？ | 3行で全体像 | 図2 | 200字 |
| 4 | ①つながりを図にする | 主機能A | 図3 | 400字 |
| 5 | ②家系図が勝手にできる | 主機能B | 図4 | 400字 |
| 6 | ③忘れたくない日を教えてくれる | 主機能C | 図5 | 350字 |
| 7 | データはどこへ行くのか | 不安をつぶす | 図6 | 300字 |
| 8 | こんなふうに使ってほしい | 使う場面の提示 | － | 300字 |
| 9 | お金の話とこれから | 障壁をなくす／締め | － | 300字 |

合計 **3,000字前後 ＋ 図6枚**。note ではこのくらいが「読み切れる長さ」の上限です。

## 2. 各セクションの設計意図

### ① つかみ ― 機能ではなく「困りごと」から入る

冒頭で「MyCIRQL というアプリを作りました」と書くと、そこで離脱されます。
**読者自身に一度考えさせる問い**から入ってください。

良い問いの条件は「答えに詰まるが、詰まったことが恥ずかしくない」こと。

- 「叔父さんの奥さんの下の名前、すぐ出てきますか？」
- 「祖母の三回忌、いつでしたっけ？」
- 「親の葬儀で渡された名簿、いま手元にありますか？」

このどれかを冒頭1行に置いて、次の行で「私は全部ダメでした」と自分を落とす。
これで読者が安心して読み進められます。

### ② きっかけ ― ここが記事のいちばん大事な部分

**ここだけは絶対に自分の実体験で書いてください。**
アプリ紹介記事で読まれるのは、機能表ではなく「なぜこの人はこれを作ったのか」です。

書くときのフォーマット：

1. **いつ・どこで・何が起きたか**（具体的な場面を1つだけ）
2. **そのとき何に困ったか**（感情ではなく状況で）
3. **既存の手段では解決しなかった理由**（連絡先アプリ／メモ／紙の名簿では足りなかった点）
4. **だから作った**（1行）

3 が入ると「なぜ新しいアプリが必要なのか」が自然に伝わります。
ここが抜けると「連絡先アプリでよくない？」と思われて終わります。

### ③〜⑥ 機能 ― 「何ができるか」ではなく「何が起きるか」で書く

機能名を見出しにしないでください。**結果を見出しにします。**

| ✕ 機能を見出しにする | ○ 結果を見出しにする |
|---|---|
| 相関図機能 | 「誰が誰の何か」を選ぶだけで、線がつながる |
| 家系図の自動生成 | 親子と夫婦を入れていたら、家系図ができていた |
| 通知機能 | 法事の日を、アプリのほうから思い出してくれる |
| CSV／PDF書き出し | 結婚式の名簿が、その場でPDFになる |

### ⑦ プライバシー ― 先回りして書く

この手のアプリで読者が最初に思うのは
**「親戚の個人情報を、知らない開発者のサーバーに預けるの？」** です。

聞かれる前に書いてください。しかも**技術用語なしで**。

> 登録した内容は、あなたの iPhone と、あなた自身の iCloud にしか保存されません。
> 私（開発者）が中身を見ることはできません。仕組み上、見られないようになっています。

例外（郵便番号→住所の検索だけ外部に問い合わせる）も、隠さず1行で書くこと。
**正直に例外を書いてあるほうが、全体の信頼が上がります。**

### ⑧ 使ってほしい場面 ― 3つに絞って具体的に

「こんな方におすすめ」を箇条書きで並べるより、**場面を1つずつ短い段落で**。

- 結婚して、相手側の親戚がまだ覚えきれていない時期
- 法事や葬儀を、自分が仕切ることになったとき
- 親から聞いた家系の話を、忘れないうちに残しておきたいとき

### ⑨ お金の話 ― 最後に、あっさり書く

途中に入れると「宣伝記事だ」と感じさせます。最後に短く。

> 図を作るところまでは無料です。
> 書き出しや画像保存をまとめて使いたくなったら、700円の買い切りだけあります。月額ではありません。

「月額ではありません」は必ず入れてください。ここが一番聞かれます。

## 3. 図6枚の仕様

図はすべて **横長（16:9 前後）／スマホで見て文字が読めるサイズ** で作ってください。
note はスマホ読者が7〜8割です。**図の中の文字は最低でも本文と同じ大きさ**が目安です。

### 図1：「わからない」の4分類
- 4つの人物アイコンを並べ、それぞれに対応するラベルを付ける
  1. 名前も顔もわからない
  2. 顔はわかるが、名前がわからない
  3. 名前はわかるが、顔と一致しない
  4. 名前も顔もわかるが、**血縁関係がわからない**
- 4つ目だけ色を変えるなど強調する（記事でいちばん核になる分類のため）
- **ねらい**：読者が「自分にも心当たりがある」と気づく。実体験（父の葬儀）から出てきた分類そのものなので、説得力が強い

### 図2：アプリの全体像（1枚で説明を終わらせる図）
- 左：「人を登録する」→ 中央：「関係を選ぶ」→ 右：「図ができる」の3ステップ矢印
- 右端から下に3本の枝：「相関図」「家系図」「名簿・PDF」
- **ねらい**：以降の説明を読まなくても構造がわかる

### 図3：相関図
- 中心に1人。放射状に「父」「母」「妻」「長女」「友人」「取引先」
- 線の上に関係名が乗っていることを強調
- **ねらい**：ドラマの相関図と同じだ、と直感させる
- ※ 実際のアプリ画面（`img/detail_hub.jpg`）をそのまま使ってもOK

### 図4：家系図（自動生成のビフォーアフター）
- 左：入力したもの＝「親子」「夫婦」の2種類の線だけ
- 右：出来上がり＝世代が縦に並び、長男・長女の順に整列した図
- 中央に太い矢印と「自動で」の一言
- **ねらい**：家系図を手で描く必要がないことが、この1枚で伝わる

### 図5：通知と書き出し
- 上段：カレンダー上に「誕生日」「命日（四十九日〜三回忌）」のピンが立つ
- 下段：チェックを付けた人だけが CSV／PDF に流れていく矢印
- **ねらい**：「実務に使える」ことを示す

### 図6：データの保管場所
- 左に iPhone、その上に鍵アイコン、右に「あなたの iCloud」
- 2つを囲む枠を描き、枠の外に「開発者」「SNS」「広告会社」を置いて **×** で切る
- 下に小さく「※郵便番号から住所を調べるときだけ、外部の住所サービスに問い合わせます」
- **ねらい**：文章より図のほうが安心感が出る、唯一のセクション

## 4. タイトル案

note はタイトルで読まれるかが8割決まります。
**「アプリを作りました」を主語にしない**のがコツです。

実体験（父の葬儀・香典返しのリストで詰まった話）が手に入ったので、これを主語にします。

1. 顔は知られているのに、私は誰なのか分からなかった。父の葬儀で作ったアプリの話
2. 香典返しのリストが作れなくて、家系図アプリを作った
3. 「どこどこのおばちゃん」が誰なのか、ついにわからないまま葬儀が終わった
4. 父の葬儀で気づいた、「わからない」には4種類あるという話
5. 血縁関係だけ、誰も教えてくれない。だから自分で図にした

**推し**：1。フックが強く、かつ「息子とは一目瞭然なのに、自分は相手がわからない」という
非対称がタイトルだけで伝わります。2 は検索（SEO）的に「香典返し」で流入する可能性もあり保険として有効。

## 5. note 側の設定チェックリスト

- [ ] **見出しは h2（大見出し）中心**に。h3 を混ぜると目次が読みにくくなります
- [ ] **アイキャッチ画像**＝図2（全体像）か、アプリの相関図スクショ。アイコン単体は弱いです
- [ ] **ハッシュタグ**：`#個人開発` `#アプリ開発` `#iOSアプリ` `#家系図` `#エッセイ`
      → `#個人開発` は note 内で回遊が起きやすいので必須
- [ ] **App Store リンクは記事内2か所**（機能説明の直後と、いちばん最後）。冒頭には置かない
- [ ] **1段落は3行まで**。note はスマホで読むと1行が短いので、PC で書くと必ず長くなります
- [ ] 公開は **平日の朝7〜8時台か、20〜22時台**
- [ ] Markdown の表は note では崩れます。**表を使いたい箇所は図にするか、箇条書きに開いてください**

## 6. 1本で終わらせず、シリーズにする場合

認知目的なら、1本目のあとに以下を続けると note 内でフォロワーが付きます。

| 回 | テーマ | ねらい |
|---|---|---|
| 1 | 今回の記事（なぜ作ったか＋何ができるか） | 入口 |
| 2 | 家系図の「日本式の並び順」を実装した話 | `#個人開発` 層に刺さる |
| 3 | 個人情報を一切預からない設計にした理由 | 信頼の積み上げ |
| 4 | ユーザーの声と、アップデートで直したところ | 継続利用の後押し |

2 は技術寄り、3 は思想寄りなので、読者層が広がります。
