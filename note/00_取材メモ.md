# 取材メモ（音声入力の書き起こし・整理版）

> 音声入力の崩れを直しただけの記録です。記事に使わなかった要素も残してあります。

## 作ったきっかけ

- **昨年、父が亡くなった。**80歳になる手前だった。
- 父のいとこ、兄弟も当然その年代。葬儀に来てくださった。
- **父と自分は顔がとても似ている。**誰がどう見ても父の子だとわかる。
  → 来てくれた人からは「こいつが息子だ」と一目瞭然だったはず。
- **しかし自分からは、その人が誰なのかわからなかった。**
  - 親族なのか、友人なのか
  - 親族だとして、いとこなのか
  - 誰の、どういう関係の人なのか
- わからないまま挨拶するので、**当たり障りのない会話にしかならない。**

## 田舎あるある：呼び名が地域名

- 「どこどこのおじちゃん」「どこどこのおばちゃん」「横浜のおばちゃん」
- **地域名＋続柄**が、その人の呼び名として通っている
- 「林田兄ちゃん」のように**苗字＋続柄**ならまだいい（あとで照合できる）
- 地域名＋おじいちゃん、で通っている人が思ったより多い

## 詰まったところ：香典返しの住所リスト

- 香典をいただいた以上、香典返しをしないといけない
- 葬儀が終わってひと段落した最後のほうで、**葬儀屋に香典返しの住所リストを作って渡す**必要がある
- ここで詰まった

### 「わからない」の4種類

1. そもそも名前を知らない
2. 顔は知っているが、名前を知らない
3. 名前は知っているが、顔と一致しない
4. 名前も顔も知っているが、**どういう血縁関係かわからない**

## 解決した方法

- 葬儀が一段落したあと、**いとこの中でも親しい人間と、手書きで家系図を作って整理した**
- → これがアプリを作ろうと思ったきっかけ

## 記事に効く点（編集メモ）

- 「顔は似ているのに、相手のことは何もわからない」という**非対称**が、この話のいちばん強いところ
- 「わからない」の4分類は、そのまま図にできる（記事の図1に採用）
- 香典返しリスト → アプリの **CSV／PDF書き出し** に直結する
- 手書きの家系図 → アプリの **家系図自動生成** に直結する
- 「次に必要になるのは、また誰かが亡くなったとき」→ **命日通知（四十九日〜三回忌）**の動機になる

## 設計思想（2回目の取材）

### なぜアプリにしたか
- 血縁関係の整理は結局コツコツ入力するしかない
- どうせ入力するなら、一番使うのはアプリだろう、ということでアプリにした

### 入力の思想：できるだけタップで済ませる
- 血縁関係を手で打つのが面倒くさいので、できるだけタップで完結するようにした
- 具体例：
  - AさんとBさんがいて、姉と弟の関係だったら、Aさんを選んでBさんを選んで関係を入れる
  - AさんとBさんには両親がいる → 「この人は父親ですか？母親ですか？」というふうに
    **質問がポンポン上がってくるので、それに答えていくだけ**で相関図・家系図が増えていく
- とにかく文字を打ちたくない、という思想で設計している
  - 本人はIT系の仕事をしていて、パソコンには強いと言われる方だが、
    それでも「スマホで文字を打つのはもっと嫌」
  - なのでタップと、写真を撮って取り込む、で済ませる方向にしている
- とはいえ名前だけはどうしても入力が要る
  - 免許証や名刺を読み込んで、名前・住所の候補を出す機能も入れてみた
  - まだ精度は上げないといけないと思っている（発展途上）
- この手のアプリで一番面倒なのは結局「入力していくこと」だと思っている
  - 家系図でも相関図でも連絡帳でも、何かは入力しないといけない
  - だったら、その「何か」をできるだけ簡素化しよう、という思想で作っている

### アルバム機能の裏話
- 葬式や結婚式あるある：「甥っ子・姪っ子、でかくなったね」という会話がよくある
- じゃあ個人のページに写真を載せて、「何歳の時の写真か」がわかるアルバムを作ろう、
  というのがアルバム機能を作ったきっかけ（半分おふざけで作った、とのこと）
- 将来的にやりたいこと（未実装の展望）：
  - 「自分が何歳のときに、この姪っ子は何歳だった」というふうに、
    **一人の人物の歴史がまるごとわかるようなもの**があるといい
  - 正直そこまで大量に写真を登録するとは思っていないが、
    気になっている子供や親戚の写真を、ぽつぽつ残していければいいと思っている

### プライバシーについて（本人の言葉）
- このアプリは個人情報を多く扱うアプリなので、開発者側でデータを抜くことは一切しない、
  というのを基本方針にしている
- 個人情報データは、端末、またはiCloudにのみ保存される
- そこから外に出すかどうかは、完全にユーザーの意思のみ
- 開発者側からデータを収集する、ということは一切しない、というのをポリシーとして掲げている

## どういう人に、どう使ってほしいか（3回目の取材）

### LINEでも電話でもない、という位置づけ
- あらゆる人が楽に使えるアプリではないと思っている
- 頻繁に連絡する道具（電話・SMS・LINE・メール）はもうすでにある。このアプリはそこを狙っていない
- このアプリが狙っているのは、**そんなに頻繁には連絡を取らないけれど、何かあったときのために連絡先を押さえておかないといけない人**の管理

### 具体的なシチュエーション①：身内の不幸
- 身内が亡くなった。連絡をしないといけない。でも「誰に連絡すればいいかわからない」
- これを防ぐために、コツコツ連絡先を貯めておいて、そのときに使う、というアプリ

### 具体的なシチュエーション②：名刺交換した取引先
- 名刺交換だけした取引先の人。半年くらい経つと「あれ、この人は何を知ってる人だっけ」「そもそもこの会社って何の会社だっけ」となる
- 忘れたころに連絡を取りたい、というシチュエーションがある

### まとめると
- 頻繁には連絡を取らないが、距離が遠すぎたり疎遠すぎたりして連絡先の登録がおろそかになっている人に対して、
  **確実に連絡先を把握しておく**という場面で使ってほしい

### おまけの使い方
- それ以前に、相関図や家系図、アルバムをPDF化して、知り合いにペロッと渡す、というくらいの気軽な使い方もできたらいいなと思っている（軽いノリでの補足）

## 「ハブ」という名前の由来（4回目の取材・訂正）

- 相関図の画面は、アプリ内では「ハブ」と呼んでいる
- ネットワーク用語としてのハブ（分岐点）の意味は知ったうえで使っている
- ただし発想の源は自転車の車輪。中心にハブがあり、そこから放射状にスポークが伸びて外側の輪を支えている、あのイメージ
- 中心の人物から関係が放射状に伸びていく画面の見た目と、車輪のハブのイメージが重なったのでこの名前にした
- 自転車が好きで、そのイメージをアプリの中に取り入れたかった、という気持ちが根底にある

## 訂正：家系図の入力仕様（3回目取材時点の誤りを修正）

- 誤：「登録するのは親子と夫婦の2種類だけ」
- 正：ハブ側では血縁・友人知人・仕事関係・自由入力まで関係を幅広く登録できる。
  そのなかで「親子」「夫婦」「兄弟姉妹」といった続柄を選ぶと、家系図がそこだけを自動で拾って世代整列する
